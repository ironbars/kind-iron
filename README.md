This is meant to go hand in hand with the [scoresvr
app](https://github.com/ironbars/scoresvr).

The deployment here is on [kind](https://kind.sigs.k8s.io/) with the nginx
ingress controller applied.

Obviously, you'll need kind and docker both installed for this to work.

You can use the script `kind-with-registry.sh` to bring up a cluster with
everything you need for the scoresvr use case (extra mounts, ingress, and local
registry).

```
./kind-with-registry.sh
```

## Playing around with Jsonnet

The Jsonnet libraries in this repo really make a general purpose config generator for kind clusters.
As such, the configuration in `scoresvr.yaml` is generated by [Jsonnet](https://jsonnet.org/). You
could adjust the variables directly in the YAML, or generate your own config using the libraries
found under `/lib`. You'd need Jsonnet installed to do this. Below is the current supported schema
for additional options to the configuration.

```json
{
  "ingress": {
    "enabled": "boolean"
  },
  "registry": {
    "enabled": "boolean"
  },
  "workers": "integer",
  "mounts": {
    "worker": [
      {
        "hostPath": "string",
        "containerPath": "string"
      }
    ],
    "controlPlane": [
      {
        "hostPath": "string",
        "containerPath": "string"
      }
    ]
  },
  "ports": {
    "worker": [
      {
        "hostPort": "integer",
        "containerPort": "integer",
        "protocol": "string"
      }
    ],
    "controlPlane": [
      {
        "hostPort": "integer",
        "containerPort": "integer",
        "protocol": "string"
      }
    ]
  }
}
```

Any of these fields (or all of them) could be empty to use the defaults, which give you a minimal
working configuration for a single node cluster. That would look like this:

```jsonnet
// mycluster.jsonnet
local cluster = import 'lib/cluster';

cluster.newCluster('mycluster')
```

If you wanted a minimal cluster with only ingress enabled, you could create a file like this:

```jsonnet
// mycluster.jsonnet
local cluster = import 'lib/cluster';

local options = {
  ingress: {
    enabled: true,
  },
};

cluster.newCluster('mycluster', options)
```

And so on. This makes the libraries suitable to generate a configuration for any sort of kind
cluster, not just for the `scoresvr` app. Using this file would is simple:

```sh
jsonnet mycluster.jsonnet
```

I'd recommend piping to [mikefarah/yq](https://github.com/mikefarah/yq) to convert to YAML, and
maybe redirect to a file after that:

```sh
jsonnet mycluster.jsonnet | yq -P > mycluster.yaml
```

You could then call the `kind-with-registry.sh` script with the new filename (**without the
extension**):

```sh
./kind-with-registry.sh mycluster
```
